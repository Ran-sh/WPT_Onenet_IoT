# ONENETapp TX/RX 双设备实现与后续验收

状态：V6.0.0 双设备网页代码已经实现。TX/RX 独立配置、首页切换、实时驾驶舱、安全控制、OneNET 云历史、±5 秒时间对齐、CSV、事件化告警和命令审计均已通过主机契约测试及本地桌面/手机 Edge 模拟验收。主仓库 `main` 的 V6.0.0 统一网关活动实现（`Arduino_Project/ESP32S3_Unified_Gateway/`）也已在控制板断功率条件下完成 STM32 ←UART→ ESP32-S3 ←MQTT→ OneNET TX、ESP32-S3 ←BLE→ nRF52840、ESP32-S3 ←MQTT→ OneNET RX 真实上/下行闭环，未发送 START/ON。仍待完成的是本次网页版本上线后的真实 OneNET 双端验收、长时间运行、异常网络恢复和受控实机危险命令验证。

## 目标设备

- `20260001`：当前实际 TX 设备名（历史说明中的 `TX_001` 仅表示逻辑角色），链路为 STM32F103 → ESP8266 兼容链路或 ESP32-S3 统一网关 → OneNET。
- `RX_001`：nRF52840 → ESP32-S3 N16R8 → OneNET 接收端设备；网关链路已在实验台完成真实上/下行验证。

两端使用独立 Product ID、Device Name、Token、请求状态、重试和命令确认链。凭据不写入仓库，不在日志或导出文件中显示。

## 配置模型

目标结构示意：

```json
{
  "tx": {
    "productId": "由用户配置",
    "deviceName": "20260001",
    "token": "仅保存在受保护的本地存储或后端"
  },
  "rx": {
    "productId": "由用户配置",
    "deviceName": "RX_001",
    "token": "仅保存在受保护的本地存储或后端"
  }
}
```

当前实现提供单设备旧配置到 TX 的一次性显式迁移、严格字段验证和版本化存储；RX 永不从旧 TX 配置推断或复制凭据。清除 TX 后旧配置不会再次复活。

## 接收端属性

统一网关实际发布到 OneNET RX 的完整属性集合（字段与固件 `Mqtt_Task_Publish_Rx_Telemetry` 一致，上报路径已在实验台断功率条件下验证）：

遥测/本地状态：

- `RX_IMon`
- `RX_Current_uA`
- `RX_BoneP`
- `RX_BoneN`
- `RX_BoneV`
- `RX_Resistance`
- `RX_Vout`
- `RX_Limit`
- `RX_Stim`
- `RX_Connected`
- `RX_Valid`
- `RX_FaultReason`
- `RX_FaultFlags`

链路/派生健康：

- `RX_BleOnline`
- `RX_MqttOnline`
- `RX_GatewayOnline`
- `RX_WifiOnline`
- `RX_TelemetryFresh`
- `RX_State`
- `RX_Safe`

命令审计：

- `RX_Command`
- `RX_CommandResult`
- `RX_CommandSequence`

`RX_LastTelemetryTime` 目前没有可信 UTC/SNTP 来源，暂不发布；OneNET 属性时间戳为当前权威时间，禁止用 `millis()` 冒充 UTC。

以上字段由统一网关上报；ONENETapp 已实现对应的 RX 属性展示、历史、告警和控制 UI。真实网页只在本次 `/device/detail` 明确确认在线且属性源时间新鲜时显示实时状态或开放危险控制。

字段类型、范围、单位和无效值策略必须与 `D:\A_Bone_healing\RXcode` 的活动协议和 ESP32 解析器共同确认后才能进入生产模型。

## 已实现页面拆分

双设备支持已包括：

1. TX/RX 独立配置和连接诊断。
2. 发射端看板、历史、告警和命令确认。
3. 接收端看板、历史、告警和命令确认。
4. TX/RX 联动曲线、数据新鲜度和未匹配点标记。
5. 设备级轮询防重入、隐藏/卸载清理和独立错误恢复。

实现不依赖“只增加几张接收端卡片”：凭据、请求、缓存、历史、告警状态、控制门控和审计均按端点隔离。

## 状态与危险控制

页面必须分别展示：发射端在线、接收端网关在线、RX MQTT、RX BLE、RX 数据有效、RX 刺激、RX 故障、数据过期、预览/真实数据和命令结果。

- TX 命令成功只认 STM32 ACK。
- RX 命令成功只认 nRF52840 状态 Notify。
- MQTT 发布、HTTP 200、BLE 写入和在线标志都不是硬件执行确认。
- BLE 断开或遥测过期时禁用 `START`，不显示旧值为实时值，不伪造 `STOP` 或安全状态。

## 时间对齐

TX/RX 历史数据按 OneNET 源时间对齐，不按数组下标连接。当前固定策略为：最大容差 ±5000ms、最近点一对一匹配；每个 RX 点最多使用一次。乱序先排序，重复时间戳保留最后值，无法匹配的 TX/RX 点分别保留并标记。当前不做插值、外推或固定时间桶聚合，因此不会用生成值掩盖缺失和数据过期。

## 物理量限制

接收端刺激电流不是无线接收功率。只有确认接收端具备真实接收功率或整流输出电流测量、单位和同步采样后，才允许计算效率；否则不生成效率曲线或用其他量替代。

## 分阶段验收

1. **已完成**：双设备配置、存储迁移、请求隔离和固定安全模型通过主机契约测试。
2. **已完成**：RX 状态、新鲜度、8 条事件化告警和危险控制门控通过离线测试；确认与恢复分离，离线/过期/错误不误恢复。
3. **已完成**：TX/RX 时间对齐覆盖容差、乱序、重复、缺失、负值和未配对点；CSV 做公式与字段转义。
4. **已完成**：本地 Edge 桌面与 390px 手机模拟验证双端页面、单端失败、告警持久化、对话框焦点和无横向溢出。
5. **部分完成**：ESP32 与 OneNET 真实上下行、命令确认已在控制板断功率实验台验证；BLE 断线恢复和长时间运行仍需完成实机验证。
6. **待完成**：推送部署后的真实 OneNET 网页验收、Cloudflare 缓存升级、弱网/Token 失效恢复，以及受控条件下的危险控制闭环。静态测试和模拟响应不能替代这些验收。
